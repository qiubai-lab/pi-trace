# Directory Map

## Root Directories

- `src/`: runtime, CLI, collection, storage/query adapters, analysis contracts, HTTP and Web application; no generated runtime data.
- `src/analysis/`: framework-independent execution/inspection semantics and legacy projections; no React, HTTP or SQLite dependencies.
- `src/storage/`: derived execution-index persistence and asynchronous writer adapter; never replaces the authoritative raw database.
- `src/workers/`: Node Worker message adapters; no domain decisions or browser code.
- `src/server/`: authenticated read-only HTTP/SSE transport; no SQL or execution interpretation.
- `src/web/`: React workbench, navigation state and typed HTTP clients; no filesystem or database capability.
- `src/testing/`: reusable synthetic execution fixtures; not production capture data.
- `bin/`: user executable entrypoints; no schema or tracing policy.
- `scripts/`: explicit installation, synthetic preview and benchmark helpers; no automatic CLI installation on package load.
- `examples/`: public-API instrumentation producers; no imports of QB Trace private internals.
- `dist/web/`, `dist/workers/`: generated production assets and standalone `.mjs` workers; regenerated by `npm run build`.
- `docs/qb-spec/context/`: approved long-lived context; change-specific behavior and evidence belong in change documents.

## Important Files

- `package.json`: Pi extension resource, published files, build and check commands.
- `src/index.ts`: Pi lifecycle adapter and collection composition root.
- `src/instrumentation.ts`: cooperative event-bus signal contract and validation.
- `src/contracts.ts`, `src/analysis/execution-contracts.ts`: raw/legacy and execution API DTO contracts.
- `src/store.ts`: authoritative schema-1 SQLite ownership and append/query primitives.
- `src/storage/execution-index.ts`: versioned rebuildable operation/history/search cache ownership.
- `src/execution-service.ts`: asynchronous execution-query application boundary.
- `src/server.ts`: loopback HTTP composition and lifecycle root.
- `src/cli-entry.ts`, `bin/qb-trace`: standalone CLI entrypoints.
- `src/web/main.tsx`, `src/web/app/App.tsx`: browser entry and application composition.
- `vite.config.ts`, `vite.workers.config.ts`, `vitest.config.ts`: executable build/test configuration.
- `README.md`, `docs/instrumentation.md`: operation, security and instrumentation entrypoints.

## Module Responsibilities

- Collection (`index`, `events`, `collector`, `config`, `diagnostics`) snapshots callback-visible data, correlates runtime identity and manages bounded fail-open buffering; independent of Web/Server.
- Raw persistence (`store`) owns schema-1 facts. Derived persistence (`storage/execution-index`) owns disposable operation revisions, source links and search indexes; its SQL does not leak into domain modules.
- Analysis (`analysis`) interprets evidence, block identity, lifecycle, inspection sections and reading masks; source data stays immutable. Storage implements its small inspection-reader port.
- Workers (`workers`, `storage/worker-writer`, `execution-service`) isolate SQLite writes and expensive query/projection work behind bounded message calls; they do not defer reading mutable Pi callback objects.
- HTTP (`server.ts`, `server/`) enforces loopback, authentication, read-only routes, safe static delivery and invalidation-stream cleanup.
- Web (`web/features/execution`) owns synchronized list/waterfall, independent Inspector, bounded remote state, Live and replay interactions; no capture or tool-execution authority.
- CLI (`cli`, `cli-entry`, `bin`) composes explicit user commands without taking over underlying policies.

## Forbidden Contents By Directory

- `src/analysis/`: no SQLite drivers/rows, filesystem reads, React components or HTTP request objects.
- `src/server/`: no SQL, collector controls or writable Web routes.
- `src/web/`: no SQLite/filesystem imports, recording/prune controls, secrets in query/path, remote scripts/fonts or automatic external Markdown resources.
- `src/workers/`: no Pi callback ownership, copied domain rules or dependence on TypeScript execution inside `node_modules`.
- `src/storage/`: no overwriting raw facts with projections and no UI component policy.
- `src/store.ts`: no HTTP formatting or presentation grouping.
- `bin/`, `scripts/`, `examples/`: no tracing/schema ownership or private cross-package imports.
- Repository-wide: no real Trace databases, credentials, runtime configuration or diagnostics checked into source control.
